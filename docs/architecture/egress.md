# Egress control — design (WP3n.3)

**Status:** accepted 2026-10-23 (ADR-0012 amendment); to be built in WP3n.3. Implements [ADR-0012](../adr/0012-network-egress.md) and its amendment of 2026-10-23. Threats: T1, T3, T12, T15 ([threat model](../02-threat-model.md)); requirement: NFR-SEC-01 ([NFRs](../01-nfr.md)).

**Reviews.** Round 1: `architect` CONSISTENT WITH FIXES, `security-reviewer` GO WITH FIXES. Round 2: `architect` CONSISTENT WITH FIXES (second pass), `security-reviewer` as attacker GO WITH FIXES, `infra-admin` vendor-fact check against official documentation, and an independent flow list written without this design and compared with it. All findings are folded in. Build review of layer 3 (2026-10-24, PR #32): `security-reviewer` as attacker GO WITH FIXES, `infra-admin` vendor-fact check READY WITH FIXES; findings folded in and each fix shown to fail its test when removed. Owner decisions (2026-10-23): Ollama in dev as a container; a separate ops proxy; host default-deny on the Spark; SNI check on the proxies; host DNS limited to `home.arpa`; XBRL taxonomies as offline packages; the UI content-security policy recorded here as a requirement.

## Goal and scope
No **stack container**, and on the Spark no host process, sends anything to the internet or the LAN except the flows named below. Refusals at the proxies and at the host firewall leave a log line; a connection that has no route leaves none (see Logging).

- **In scope:** the containers of the Compose stack (`just up`, generated by `aspire publish` plus the egress overlay) on the desktop, in CI and on the Spark; on the Spark, the host itself.
- **Out of scope:** `aspire run` (its host processes and the containers it starts; development data only) and dev tooling: the dev container (WP2.4), Claude Code sessions (ADR-0015), CI build jobs (ADR-0004).

## Network membership matrix
Internal networks are cut so that a compromised container reaches only what its job needs. The Compose lint (L1) enforces the matrix from its copy as data, `deploy/compose/policy.json`, where each service is placed by its `aetherspark.role` label. The table below is prose, so no lint compares the two: a change to either is a design change and changes both in the same pull request.

| Network | Members | Why |
|---|---|---|
| `ingress` | Traefik | Only published ports |
| `edge` (internal) | Traefik; UI/API services; Keycloak's public endpoint; Grafana; ntfy | Routing to user-facing endpoints |
| `auth-<group>` (internal, one per group) | Keycloak's back-channel listener; the services of one group that validate tokens or get client-credentials tokens | OIDC discovery, JWKS, tokens. Keycloak's admin API listens on a separate port reachable only through `edge` (owner) |
| `pki` (internal) | step-ca; Traefik; services that renew their own certificates | Certificate issuance and renewal. The NAS (from WP6.6) renews through Traefik on the ingress rule |
| `llm` (internal) | LiteLLM; vLLM/Ollama; agent host; pipeline (embeddings) | Model calls through the gateway only |
| `mcp` (internal) | agent host; MCP servers | Tool calls |
| `data-read` (internal) | MCP servers; verifier; Postgres; ClickHouse (read-only roles) | Queries |
| `ingest` (internal) | ingester; price job; pipeline; Postgres; ClickHouse (**write-only roles** for the ingester and the price job: insert into their tables, no select on other tables) | Writes |
| `obs-<group>` (internal, one per group) | the services of one group (push only); the OTel collector | Telemetry in; Grafana/Loki queried through `edge` only |
| `egress-runtime` (internal) / `out-runtime` | ingester, price job / runtime proxy | Runtime egress |
| `egress-ops` (internal) / `out-ops` | owner-started jobs (pull jobs, builds, taxonomy download) / ops proxy | Ops egress |
| `backup` | restic job | NAS only |

**Groups** for the per-group `auth-` and `obs-` networks: `ingest` (ingester, price job, pipeline), `llm` (LiteLLM, serving), `agents` (agent host, MCP servers, verifier), `edge` (UI/API services, Grafana, ntfy). Keycloak and the OTel collector join every group's network; services of different groups never meet on them. A network shared by "every service" would put the ingester next to LLM serving and MCP servers, which the matrix exists to prevent.

Rules the lint checks: the generated Compose's default network is removed by the overlay, and every service is on networks of this matrix only; the ingester and the price job share no network with LLM serving, MCP servers, the agent host, Grafana/Loki query APIs or Keycloak's admin listener; LLM serving joins only `llm`, `auth-llm` and `obs-llm`; no container except the proxies joins an `out-*` network; only Traefik joins `ingress`.

## Three layers

| Layer | What it does | Desktop | CI (GitHub-hosted, amd64 + arm64) | Spark |
|---|---|---|---|---|
| **1. Internal networks** | All stack containers except Traefik, the two proxies (outbound side) and restic join only `internal: true` networks: no route to the internet. IPv6 off on every network (`enable_ipv6: false`). **Note:** on Linux a container on an internal network can still reach the host on the bridge address (Docker documentation); layer 3 closes that | Yes | Yes | Yes |
| **2. Proxies** | Two Squid containers (runtime, ops), each with its own config and allowlist, SNI checked, no decryption | Yes | Yes | Yes |
| **3. Host firewall** | `DOCKER-USER` (forwarded traffic), host `INPUT` from Docker bridges, and on the Spark host `OUTPUT` | **No**: Docker Desktop's VM is not under our control | Yes | Yes |

### Layer 3 rules
- **Backend pinned:** Docker Engine with the **iptables backend** (`iptables-nft`), which provides `DOCKER-USER`; the native nftables backend has no such chain and is experimental. Engine **≥ 26.0** supported (DNS fix for internal-only containers, CVE-2024-29018), tested on 28.x in CI; DGX OS 7.6 ships 29.x, which the Spark run of the suite covers. Same backend on the Spark and in CI. The rule script refuses to apply, and Docker's start fails, if `daemon.json` or `docker info` show another firewall backend, or if `ufw` or `firewalld` is active.
- **Bridge names:** every network of the matrix sets `com.docker.network.bridge.name` to an `as-` name (`as-out-runtime`, `as-backup`, `as-ingress`, …), so the rules match networks by interface. Flows are granted to exact names only; the wildcards (`docker0`, `br-+`, `as-+`) only drop, so unnamed networks get no flow at all. `install.sh` refuses a non-Docker interface that matches a wildcard (a host bridge `br-lan` would otherwise lose its traffic). Internal networks also pin `gateway` to `.1`.
- **Source check on Docker bridges** (raw table, before connection tracking): a packet from a bridge must carry a source address routed back through that bridge, or it is logged and dropped. Containers have `NET_RAW` by default; without the check, a container could forge another container's address and ride its open connection, for example a one-way DNS channel through a proxy's lookup (E22).
- **No userland proxy** (`"userland-proxy": false` in `daemon.json`, checked like the DNS setting): with it, published ports also answer on the host's IPv6 addresses, link-local included, and those connections never pass `DOCKER-USER` (E19).
- **`DOCKER-USER`, IPv4:** accept `ct state established,related`; new connections from any Docker bridge to `ingress` dropped (Docker 29 lets other networks reach published ports through a host address); then traffic between two Docker bridges is handed back to Docker's own isolation rules; `out-runtime` and `out-ops` may reach public addresses on TCP 443 and the upstream resolver on 53, nothing else (RFC 1918, link-local, the router except DNS, the NAS dropped); `backup` only the NAS address and port; `ingress` accepts new TCP 443 from the Home subnet and, from WP6.6, from the NAS's address; everything else from Docker bridges is dropped. No ICMP out. Forwarding between non-Docker interfaces is dropped (the Spark is multi-homed).
- **Host `INPUT` from Docker bridges: default-deny**, after accepting `ct state established,related` (the replies to the host's own connections, e.g. to the ops proxy). Containers must not open connections to host services (sshd, exporters, the Docker API) through the bridge address. Gateway mode `isolated` is not used: the host must still reach the ops proxy for apt and image pulls.
- **IPv6:** dropped entirely from Docker bridges, in addition to `enable_ipv6: false`: nothing is forwarded (`DOCKER-USER` for IPv6, since Docker puts its own jump first in `FORWARD` at every start) and Docker bridges reach no host service.
- **Docker's DNS upstreams in `daemon.json`** (`"dns"`: the same resolvers). Docker's embedded resolver sends lookups for upstreams it took from the host's `resolv.conf` from the **host's** network namespace (`ExtServers: [host(…)]` in a container's `resolv.conf`), past `DOCKER-USER`: every container on a non-internal network could then resolve any name, a DNS channel out for Traefik and restic, and on the Spark host `OUTPUT` would block the proxies' lookups. Upstreams set in `daemon.json` are queried from the **container's** namespace, so `DOCKER-USER` decides: only `as-out-*` reach the resolver. The rule check fails without this setting. Since Engine 28.0.0 ("DNS nameservers read from the host's /etc/resolv.conf are now always accessed from the host's network namespace", release notes); found while building on 28.0.4 and confirmed in the resolver's source.
- **Host `OUTPUT` on the Spark, default-deny** (complete list and the host's `INPUT` in [spark-host.md](spark-host.md)): loopback; host → containers only to the ops proxy and the stack's collector; NTP to the router; DNS (port 53) to the router **only for the local resolver's own user** (`systemd-resolved`), which forwards only `~home.arpa` and has no default route, so no other process and no other name reaches the router's forwarder; apt (sources switched to HTTPS, `ports.ubuntu.com` for arm64), the Docker daemon's image pulls (`proxies` in `daemon.json`) and fwupd (its proxy setting) through the ops proxy's fixed address on `egress-ops`, so they work only while it runs; replies.
- **Order at boot:** the rule set is a systemd unit ordered after any other firewall service and before `docker.service`, and Docker requires it, so no container with `restart:` starts before the rules exist. A drop-in for `docker.service` re-applies the rules after every Docker start (Docker re-inserts its jumps) and fails the start if they are not in place; it is a check after the fact, not a gate, since dockerd starts restart-policy containers before it reports ready. Docker keeps the contents of `DOCKER-USER` across restarts. Re-apply with `systemctl reload aetherspark-egress-rules`, never `restart`: Docker requires the unit, so restarting it restarts Docker. A reboot test proves the order.
- **`check` compares every rule** with the rendered rule set (loaded into a scratch network namespace, so both sides print in the same normalised form), plus the jumps and Docker's settings; an added or edited rule fails it. It runs at every Docker start; a timer with an alert follows with ADR-0011's alerting.
- **Host `OUTPUT` rules (WP6.2)** are in this rule script (its host mode, [spark-host.md](spark-host.md)), never into a ruleset loaded with `flush ruleset` (that would remove these rules); `install.sh` refuses an enabled `nftables.service` whose configuration flushes the ruleset.
- **Bootstrap (WP6.2):** build or load the egress proxy image, pull or load the pinned BuildKit and base images, then enable host `OUTPUT` default-deny. Later digest bumps are pulled through the running ops proxy.
- **Every drop is logged**, with a prefix and a log budget per source and destination pair (`hashlimit`), so a flood from one container cannot hide another container's attempt. Until WP5a.5 that is a kernel log line; from WP5a.5 the log shipper forwards it to the `agent-audit` stream (ADR-0019).

## The two proxies
- **Runtime proxy** (profile `core`) and **ops proxy** (profile **`egress-ops`**, `just egress-ops up` / `down`) take their hosts from the literal allowlist below; L2 compares the proxies' files with it.
- **NuGet restores** run with `NUGET_CERT_REVOCATION_MODE=offline`: package signatures are still verified, and restores stay pinned to lock-file hashes and the signed-checksums check (ADR-0009); certificate revocation lists, which use plain HTTP on port 80, are not fetched.
- **Agents, LLM serving, MCP servers, the verifier and databases join neither proxy network.**
- **SNI check:** each proxy reads the TLS ClientHello name without decrypting (`ssl_bump peek` at step 1) and splices the connection only if `ssl::server_name` matches the same allowlist as the `CONNECT` host; otherwise it terminates. No interception: allowed tunnels are only peeked at and spliced. This stops a second site name inside an allowed tunnel (domain fronting through a CDN).
- **Refused `CONNECT`s:** on an `ssl-bump` port Squid 6 always accepts a refused `CONNECT` (`200`), opens no upstream connection and serves its `403` page inside TLS; the `ssl_bump` rules cannot change this (Squid forces a bump to deliver the error; only `407` is exempt). The certificate it uses is self-signed, made fresh in tmpfs at each start, trusted by nobody and signs nothing else (`generate-host-certificates=off`), so a client sees a TLS failure, or with verification off, Squid's `403`. The log shows `TCP_DENIED` with no bytes from upstream; E3, E4 and E6 check for exactly this.
- **Hardening (both):** `CONNECT` to port 443 only, every other method denied; `dstdomain -n`; explicit denies for IP literals (IPv4, bracketed IPv6, integer and hex forms) and trailing-dot or look-alike names; `cache deny all`; `icp_port 0`, `htcp_port 0`, `snmp_port 0`; `pinger_enable off` where the build supports it; `http_access deny manager`; `via off`; `forwarded_for delete`; no `cache_peer`, no URL rewriters; listening on the internal network address only. `squid -k parse` runs in the tests, so an unsupported directive fails early.
- **Upload volume alert (runtime proxy):** the ingester sends almost nothing upstream; a tunnel whose client-sent bytes exceed a small threshold raises an alert.
- **Image:** own image (`deploy/compose/egress/Dockerfile`), because `ssl_bump` needs Squid built with OpenSSL and Canonical's `ubuntu/squid` image ships the GnuTLS build. It installs Ubuntu's `squid-openssl` at an exact version from `noble-security` on the digest-pinned `ubuntu:24.04` base, over HTTPS with the CA bundle copied from a pinned stage; the build fails if Squid lacks OpenSSL. Not an Ubuntu snapshot date: `snapshot.ubuntu.com` does not serve `ports.ubuntu.com`, so arm64 could not use it. Security fixes arrive as Ubuntu security notices for the `squid` and `openssl` packages; the archive then drops the pinned version, the build fails, and the pin is bumped.

## Builds and image pulls
- **Image builds** (WP6.4 on the Spark): a `buildx` builder with the `docker-container` driver on `egress-ops` (`--driver-opt network=egress-ops`, `env.HTTPS_PROXY`, `env.NO_PROXY`), plus the proxy as build arguments for `RUN` steps. The default bridge has no way out (layer 3).
- **HTTPS-only apt in builds:** base images without `ca-certificates` get the CA bundle copied from a pinned stage before any `apt-get`; no plain-HTTP fetches.
- **Image pulls** by the Docker daemon go through the ops proxy on the Spark. On the desktop, Docker Desktop pulls directly: development images only, an accepted residual.

## Model store and taxonomies
- **Model store:** written only by one-shot **pull jobs** in `egress-ops` (Hugging Face/NGC downloads; `ollama-pull` in dev) that download and verify revision and checksum (ADR-0006) and never load model code. Serving containers (vLLM, Ollama) mount it **read-only** and never join a proxy network. A malicious model therefore cannot leave data in the store for a later ops session to upload.
- **XBRL taxonomies:** taxonomy packages are downloaded in an ops session, checksummed, and mounted read-only into the pipeline; Arelle runs offline. The pipeline has no proxy route.
- **Ops jobs mount no runtime data volumes**; the model store is mounted writable only by pull jobs.

## Inputs to the runtime flows (covert channel)
The ingester and the price job take company identifiers (CIK, accession numbers, tickers) only from the owner-maintained universe (ADR-0020), each validated by format. No agent tool enqueues ingestion or passes job arguments, and the ingester never follows a URL found inside a filing.

## DNS
- **Containers:** Docker service names only. Containers attached only to internal networks get no answer for external names (Engine ≥ 26). The two proxies are on an internal and an outbound network and resolve through the upstream resolver, which is what they need. Containers on other non-internal networks (Traefik, restic) get no external names either: with the upstream in `daemon.json` their lookups leave from their own namespace and `DOCKER-USER` drops them (see Layer 3 rules; E9). A failing E8 blocks the release; it is not worked around inside containers.
- **Spark host:** resolves only `home.arpa`. `systemd-resolved` forwards only `~home.arpa` to the router and has no default route, and host `OUTPUT` lets only the resolver's own user send DNS to the router. The host needs no external names because apt, pulls and fwupd resolve at the proxy. This closes DNS tunnelling from host processes; E12 checks a direct query to the router as root.

## Phone-home settings, off and tested
- **Stack:** Traefik `checkNewVersion` and `sendAnonymousUsage`; LiteLLM's remote model cost map (`LITELLM_LOCAL_MODEL_COST_MAP=True`) and telemetry; Grafana update checks, reporting and plugin updates; vLLM usage statistics (`VLLM_NO_USAGE_STATS=1`, `DO_NOT_TRACK=1`); Hugging Face Hub lookups at serving start (`HF_HUB_OFFLINE=1`). L1 checks the rendered settings.
- **Spark host:** `apt-daily`, `apt-daily-upgrade` and `unattended-upgrades` timers, `motd-news`, snap refresh (or no snapd), `apport`/`whoopsie`, Ubuntu Pro/Landscape, the `fwupd-refresh` timer, NVIDIA telemetry and any connectivity check disabled; security updates run in owner ops sessions (patch latency is an owner duty). E14 (cold start with the WAN cut) proves no service tries to reach out.

## UI requirement (P3a/P5a)
A report can carry text from an injected filing. If the browser rendered a remote image or followed an automatic link in it, the owner's browser on the Home network would send data out. So: Traefik sets a strict Content-Security-Policy (`default-src 'self'`; images, scripts and fetches from the app only), and the UI renders model text without remote images or automatic links. Test E15 runs with the UI.

## Compose and config lint (CI, every pull request that touches them)
- **L1 — rendered Compose:** rejects `network_mode: host` or `service:…`; `privileged`; any `cap_add` outside policy.json's short list (file ownership, user switching, low ports), so never `NET_ADMIN`, `NET_RAW`, `SYS_ADMIN` or `ALL`; `pid`, `ipc`, `uts`, `userns_mode` or `cgroup` shared with the host or another container; `security_opt` that switches seccomp, AppArmor or SELinux off; host `devices`; build-time `network`, `privileged` or `entitlements`; a service without a known `aetherspark.role` label; a role on a network with a way out (`ingress`, `out-*`, `backup`) whose image is not the one policy.json binds to it, so a label alone does not make a proxy; an `external` network, or one named other than the project's own; a network whose `internal` setting differs from the matrix; a mount that reaches the Docker or containerd API, network namespaces, `/proc`, `/sys`, `/dev` or `/run`, a path below one or a parent such as `/` (also through a named volume's `device`, a `config` or a `secret`), so no `docker.sock` (Traefik uses the file provider); published ports on anything but Traefik; undeclared networks; a matrix network without its `as-` bridge name; a network driver other than `bridge` (`macvlan` and `ipvlan` go straight out of the NIC, never forwarded); the bridge options `gateway_mode_ipv4` and `enable_ip_masquerade`; `network_mode: container:…` (it inherits the other container's networks, e.g. a proxy's `out-*`); a service that does not drop `NET_RAW` (Docker grants it by default); per-service `dns`, `dns_search` or `dns_opt`; `enable_ipv6: true`; any violation of the membership matrix; a writable model-store mount outside pull jobs; a missing phone-home setting. A fixture with each forbidden setting must fail (`deploy/compose/tests/`, part of `just ci`). L1 renders `deploy/compose/egress/compose.yaml` with every profile; from P3a it renders the whole stack.
- **L2 — allowlists:** each proxy's allowlist file equals the list in this note, so an added host needs a design change.
- **L3 — config:** `squid -k parse` on both configs with their real mounts in a freshly built image (the entrypoint's `parse` mode), and a broken config must fail it; the layer-3 rules, rendered from the example settings with and without a backup flow, load in a scratch namespace (`egress-rules.sh lint`; root, so CI only).
- **Run:** `just egress-lint` (`tests/egress/lint.sh`); in CI the `egress-lint` job, for any change to `deploy/compose/`, `deploy/host/`, `tests/egress/` or this note.

## Logging (ADR-0011, ADR-0019)
- Squid access logs (both proxies): time, client address, method, host, port, SNI, decision, bytes in each direction. `strip_query_terms on` (the default); no bodies.
- Layer-3 drops: kernel log with a prefix; forwarded to `agent-audit` from WP5a.5.
- A connection with no route leaves no trace; detection for agents relies on ADR-0019's tool-call audit.
- NFR-SEC-01's check reads both logs.

## Where it lives
- `deploy/compose/egress/`: both Squid configs and allowlists, the overlay with all networks of the matrix, profiles `core` and `egress-ops`.
- `deploy/host/`: the rule script (`DOCKER-USER`, `INPUT`, IPv6, and the Spark's host mode; `baseline`, `apply`, `check`, `remove`, `lint`), the systemd unit, the check timer, the `docker.service` drop-in, `install.sh` (also sets `"dns"` in `daemon.json`) and an example settings file; the Spark's host `INPUT` and `OUTPUT` rules, the rest of the `daemon.json` fragment and the resolver settings follow with the host role (WP6.2, [spark-host.md](spark-host.md)). Applied by the host role on the Spark and by the CI job.
- `deploy/compose/`: `policy.json` (the matrix and Compose rules as data) and `lint.py` (L1, L2) with its fixture tests.
- `tests/egress/`: the tests below (`just egress-test`), the lint runner (`just egress-lint`) and the Spark host lab (`just host-lab`, [spark-host.md](spark-host.md)).

## Restore drills
The quarterly restore drill and the cutover dress rehearsal (roadmap slip policy) restore onto the desktop with the same Compose overlay and layers as dev, on no other network; a drill VM, if used, gets the same overlay and is not attached to the AetherSpark network.

## How it is built
- **Observe, then allow:** the first run of each new service is deny-all with logging; every attempt in the drop log is either a flow this note names or a bug, and is resolved before the service is accepted.
- **Break-it test (M1)** before WP3n.3 is closed, and again whenever a rule changes.

## Accepted residuals
- **Desktop without layer 3:** Traefik (`ingress`) and restic (`backup`) can reach anything from the desktop, and containers can reach the Docker Desktop VM; compensated by the lints, the tests after updates, and development data only (ADR-0015, ADR-0020).
- **Docker Desktop pulls images directly** (development images only).
- **Ops sessions:** while the ops proxy is up, an install script in an ops job could upload to an allowed host; compensated by owner-started, short-lived jobs without runtime data mounts, and E5.
- **A compromised proxy** reaches any public address on 443 and the resolver; compensated by the Squid hardening and SNI check, the pinned image and the upload alert. Nothing at home answers on a public address: the router's WAN address is private (double NAT behind the ISP box), so the private-range drop covers it, and the ISP box has remote access off and no port shares (network runbook, 0.5 and 2b). That must stay so: a later port share or remote access on the ISP box would be reachable from the proxies.
- **No TLS decryption:** data inside an allowed SNI to an allowed host (for example in SEC request paths) is limited by the input rule and the upload alert, not by content inspection.
- **Covert timing or volume channels** through the runtime flows: limited to what the ingester's deterministic requests carry.
