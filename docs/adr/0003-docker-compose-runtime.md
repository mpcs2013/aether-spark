# ADR-0003: Docker Compose as single-node runtime
- **Status:** Accepted · **Date:** 2026-10-03
## Decision
Docker Compose (v2) on DGX OS with NVIDIA Container Toolkit. Compose files generated by `aspire publish` plus checked-in overlays (`deploy/compose/*.override.yml`) for GPU, memory limits and volumes. Profiles: `core`, `data`, `ai`, `ops`, `dev`.

*Note (2026-10-23):* a further profile, **`egress-ops`**, runs the ops egress proxy only while an owner-started job runs (ADR-0012 amendment 2026-10-23). It is a separate name because `ops` (observability, restic) runs all the time, and starting it must never open the ops allowlist.
## Consequences
Low overhead, simple ops; no self-healing across nodes, no rolling updates (acceptable for single user).
## Alternatives considered
k3s — Kubernetes semantics and multi-node readiness, but adds ~1–2 GB memory and operational complexity on a single box.
## Revisit trigger
A second Spark (ConnectX-7 pairing) or > 1 concurrent user group.
